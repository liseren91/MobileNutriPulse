# NutriPulse

Личный ИИ-диетолог и таймер питания. Помогает есть регулярно, готовить быстро (5–10 минут) и не терять прогресс, даже если день пошёл не по плану.

Приложение работает как веб-клиент и как нативное iOS-приложение через Capacitor. Бэкенда нет: данные хранятся на устройстве, а ИИ вызывается напрямую из клиента.

---

## О продукте

NutriPulse заточен не на идеальный рацион, а на **регулярность**. Типичная боль пользователя — пропускать еду, потом срываться на фастфуд и бросать трекинг. Приложение решает это тремя вещами:

1. **Таймер приёмов пищи** — считает время до следующего приёма, учитывает сон и завтрак, напоминает, когда пора есть.
2. **План на 3 дня** — Gemini генерирует завтрак, обед, ужин и перекус с рецептами на 5–10 минут и общим списком покупок.
3. **Мягкий коучинг** — чат с диетологом, разбор еды вне плана (текст или фото), статистика БЖУ и трофеи за 3-дневные циклы.

Интерфейс на русском и английском. Онбординг спрашивает имя, цель (похудение, мышцы, привычки, энергия), ограничения в еде, интервал между приёмами, время отбоя и подъёма.

### Экраны

| Экран | Что делает |
| --- | --- |
| Онбординг | Профиль, цели, режим дня, язык |
| Дашборд | Таймер, «Я поел», уведомления, еда вне плана, дневной обзор |
| План | Рецепты на 3 дня, отметка выполненных блюд |

| Чат-коуч | Диалог с Gemini от лица диетолога |
| Профиль | Цели по калориям и БЖУ, любимые/исключённые продукты, трофеи |

## Сложности

Проект выглядит как простой React-клиент, но основная сложность — совместить ИИ, локальное состояние и нативный iOS без сервера.

### Нет бэкенда

Профиль, план, список покупок, съеденное и история живут в `localStorage`. Это упрощает запуск, но даёт ограничения:

- данные не синхронизируются между устройствами;
- сброс браузера или переустановка приложения стирает прогресс;
- ключ Gemini попадает в клиентский бандл при сборке (см. `vite.config.ts`).

Для продакшена ключ лучше проксировать через свой API, а не вшивать в приложение.

### Gemini как источник правды

План, БЖУ, калории, разбор фото и трофеи приходят из `gemini-2.5-flash` со structured JSON. Модель иногда:

- отдаёт неполный JSON или пустой ответ;
- оценивает калории и макросы приблизительно;
- путает язык, если в промпте недостаточно жёстко зафиксирован RU/EN.

Поэтому в коде есть запасные пути: сохранение еды без БЖУ, дефолтное распределение макросов, повторная генерация плана.

### Согласованность локальных данных

Съеденные блюда (`eatenMeals`) и дневная история (`dailyHistory`) легко разъезжаются: дубликаты по дате, UTC vs локальный день, повторная отметка одного приёма. История пересчитывается из `eatenMeals`, а даты пишутся в локальной таймзоне пользователя.

Привязка кнопки «Я поел» к конкретному блюду плана тоже эвристика: текущий день плана (цикл 1–3) + тип еды по часу (завтрак / обед / ужин / перекус).

### Capacitor и уведомления на iOS

На вебе используются Notification API, на телефоне — `@capacitor/local-notifications`. Для iOS это потребовало патчей через `patch-package`:

- `@capacitor/local-notifications` — типы разрешений `.alert` заменены на `.banner` / `.list` (iOS 15+);
- `@capacitor/ios` — правки импортов Cordova/ObjC, без которых нативная сборка падает.

Патчи применяются автоматически в `postinstall`. Без них `npm install` + Xcode-сборка часто ломается.

Уведомление «пора есть» планируется, когда таймер истёк и приложение ещё живо. Фоновый scheduling на iOS ограничен: если процесс убит, напоминание может не прийти.

### Мобильный UX

Safe area (notch, home indicator), `viewport-fit=cover`, отключение зума и выделения текста, камера и галерея для фото еды. На iOS нужны описания доступа к камере и фото в `Info.plist`.

Ключ API для нативной сборки нужно задать **до** `vite build`: Capacitor упаковывает уже собранный `dist`.

## Установка

### Что нужно

- Node.js 20+ (рекомендуется LTS) и npm
- ключ [Google AI Studio / Gemini](https://aistudio.google.com/apikey)

Для iOS дополнительно:

- macOS
- Xcode 15+ и Command Line Tools
- CocoaPods (`sudo gem install cocoapods` или через Homebrew)
- Apple ID для запуска на симуляторе или устройстве

### 1. Клонировать и поставить зависимости

```bash
git clone <url-репозитория>
cd MobileNutriPulse
npm install
```

`postinstall` сам применит патчи Capacitor из `patches/`.

### 2. Ключ Gemini

В корне проекта создайте файл `.env.local`:

```env
GEMINI_API_KEY=ваш_ключ
```

Подойдёт и `VITE_GEMINI_API_KEY`. Vite подхватывает оба имени и прокидывает значение в `process.env.API_KEY` при dev и build.

Файл `.env.local` в git не коммитится (`*.local` в `.gitignore`).

### 3. Запуск в браузере

```bash
npm run dev
```

Откроется `http://localhost:3000`. Онбординг → дашборд → «Создать план».

Полезные команды:

```bash
npm run build      # сборка в dist/
npm run preview    # локальный просмотр production-сборки
```

### 4. iOS (только macOS)

```bash
npm run build:ios   # vite build + cap sync ios
npm run ios:open    # открыть проект в Xcode
```

В Xcode:

1. Выберите target **App**.
2. В Signing & Capabilities укажите свою Team.
3. Запустите на симуляторе или устройстве.

Повторная синхронизация веб-сборки в нативный проект:

```bash
npm run ios:sync
```

Если после `npm install` Xcode ругается на Capacitor/Cordova headers — проверьте, что папка `patches/` на месте и `postinstall` отработал. При необходимости:

```bash
npx patch-package
cd ios/App && pod install
```

### Частые проблемы

| Симптом | Что проверить |
| --- | --- |
| `API Key is missing` | Есть ли `.env.local`, перезапущен ли `npm run dev` |
| План не создаётся | Ключ Gemini, квота, сеть; в консоли будет ошибка |
| На iOS нет ИИ | Ключ должен быть задан **до** `npm run build:ios` |
| Нет уведомлений | Разрешение в браузере / настройках iOS; приложение не в фоне надолго |
| Сборка iOS падает на headers | `npx patch-package`, затем `pod install` |
| Пустой экран после обновления | Старый профиль в `localStorage`; очистите данные сайта или переустановите приложение |

## Важно про ключ API

Ключ сейчас вшивается в клиент. Это нормально для локальной разработки и своего устройства, но **нельзя** выкладывать такой билд в App Store или на публичный хостинг: ключ можно достать из бандла.

Минимальный безопасный вариант — маленький прокси-сервер, который держит ключ у себя и проксирует запросы к Gemini.
